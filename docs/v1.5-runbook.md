# REDO v1.5 — Design Blueprint Engine: operations runbook

Audience: whoever installs, demos or operates REDO. Everything here describes what the code does today;
the *Known limitations* section is deliberately blunt.

## 1. What v1.5 added

A website is now generated from four separate, versioned things (PRD v1.5):

| Concept | What it decides | Where it lives |
|---|---|---|
| **Category** (7) | How a user *discovers* directions. A filter, never a constraint. | `database/catalogue/design-catalogue.json` |
| **Direction** (12) | Visual personality: palette, font pairing, density, shape, imagery style, layout preferences | same file (`token_overrides`, `layout_preferences`, `art_style`) |
| **Blueprint** (7) | Information architecture: which sections, in what order, which are optional | `database/catalogue/blueprints/*.json` |
| **Section component** (34 variants) | The trusted Blade implementation of one section | `config/section_registry.php` + `resources/views/blueprints/sections/` |

Flow: Website DNA → recommendation → user picks direction + layout → **content mapping** (verified source content
into the layout's slots, nothing invented) → **DesignSpec 1.5** (validated against `database/catalogue/schemas/design-spec-1.5.schema.json`)
→ trusted renderer → real-browser QA (+ bounded refinement) → before/after reveal → HTML export / publish (paid plans).

Model output never selects a view, a variant, a URL or CSS. The renderer reads only the validated `v15` block.

## 2. Clean install (repeatable)

```bash
composer install && npm install --ignore-scripts
cp .env.example .env && php artisan key:generate
php artisan migrate --force
npm run build                     # builds CSS AND the 19 approved self-hosted fonts (needs network once)
php artisan storage:link
php artisan db:seed               # catalogue, plans, demo fixtures, admin
npx playwright install chromium   # only on a machine that runs browser QA / captures
```

Then, on a machine with Node + Playwright:

```bash
php artisan directions:capture        # real screenshot of each direction's showcase site + uniqueness check
php artisan blueprints:capture        # preview QA for every blueprint × direction pair (marks them "ready")
php artisan fixtures:capture-originals
php artisan redo:demo                 # the whole story, one command (see §7)
```

`composer dev` runs the web server, queue worker and Vite. **Restart it after pulling code**: a long-running
`queue:work` keeps old code in memory (use `queue:listen` in development).

## 3. Configuration

| Setting | Default | Purpose |
|---|---|---|
| `REDO_ACTIVATE_V15_DIRECTIONS` | `true` | Offer the 12 v1.5 directions; retire the superseded legacy six from *selection* (existing runs still render). `false` + `db:seed --class=CatalogueSeeder` rolls back. |
| `REDO_BROWSER_PROVIDER` | `local` | `local` (Playwright on this machine) or `browserless` (remote). |
| `BROWSERLESS_URL` / `BROWSERLESS_TOKEN` | — / — | Remote provider. **Unverified against a live account** (see §9). |
| `REDO_QA_MAX_REFINEMENTS` | `2` | Automatic fix-and-recheck passes per spec lineage. |
| `REDO_QA_MAX_REPORTS_PER_DAY` | `20` | Browser QA runs per project per day (refinement passes count). HTTP 429 beyond. |
| `REDO_RETAIN_QA_SCREENSHOT_DAYS` | `30` | QA screenshots kept this long. |
| `REDO_RETAIN_TEMP_HOURS` | `24` | Abandoned temp build directories kept this long. |
| `REDO_RETAIN_EXPORT_DAYS_AFTER_EXPIRY` | `7` | Export ZIPs (download window is 24h) deleted this long after expiry. |
| `REDO_SOURCE_CAPTURE` | `true` only when `APP_ENV=local` | Read customer sites with a real browser (JavaScript sites, bot-challenge sites) and take the genuine "before" screenshot. See §6b. |
| `REDO_SOURCE_CAPTURE_PAGES` / `_SECONDS` | `4` / `75` | Pages read and the time budget for one capture. |
| `CRAWLER_*` | see `config/crawler.php` | Page, depth, byte, redirect and timeout limits for the source crawl. |

## 4. Commands

| Command | What it does |
|---|---|
| `directions:capture [id]` | Renders each direction's showcase with the production renderer, screenshots it (desktop hero, full page, mobile) and fails if any two are visually near-identical or any page logs a console error. Writes `direction-previews/manifest.json`. |
| `blueprints:capture [id] [--direction=]` | Preview QA at desktop/tablet/mobile. A blueprint is **selectable only after this passes**. No web server needed. |
| `fixtures:capture-originals` | Renders the *illustrative* original site for each demo fixture (labelled as such in the UI). |
| `redo:demo [fixture] [--direction=] [--skip-qa]` | Clean end-to-end demo with no live model calls. Repeatable. |
| `redo:prune [--dry-run]` | Retention (scheduled daily 03:30). Needs `schedule:run` from cron. |

Adding a direction or blueprint: edit the JSON, add its showcase sample under `database/catalogue/samples/`
(`{blueprint}.{direction}.json`), run `db:seed --class=CatalogueSeeder`, then the two capture commands.
The test suite refuses unregistered variants, missing showcases, palettes below WCAG 4.5:1 and directions that share an art style or font pairing.

## 5. Failure modes and what the system does

| Situation | Behaviour |
|---|---|
| Meta / model API down during generation | Selection marked failed with a generic message; the user can retry. No partial spec is saved. |
| Blueprint mapping/validation fails | The redesign is **not lost**: the legacy spec renders as before; the errors are logged. |
| Required content missing (e.g. no contact email for a required form) | Section omitted, spec marked **partial**, reason shown to the user. Nothing is invented. |
| Browser provider outage / misconfigured | QA report → `failed` with an actionable, non-leaking message. No refinement is attempted. |
| Worker killed mid-QA (timeout, deploy) | `failed()` hook marks the report failed; status polling also gives up after 15 minutes. |
| User double-clicks "Run QA" | Returns the in-flight report; no second run. |
| QA that cannot run its own checks | Reported as a **critical failed finding**, never as a pass. |
| Crawl target resolves internally, redirects internally, or rebinds DNS | Refused before any request (§6). |
| Subpage returns HTTP 4xx/5xx | Skipped with a warning; its text never becomes evidence. |
| Temp build dirs left by a crash | Removed by `redo:prune` after 24h; also removed in `finally` on the normal paths. |

## 6. Security model

* **SSRF.** `SsrfGuard` + `SafeHttpFetcher`: http(s) only, no credentials, every resolved IP must be public (including
  CGNAT, NAT64, 6to4, Teredo, benchmarking, multicast and cloud-metadata ranges), re-checked on **every redirect hop**, DNS pinned
  per hop via `CURLOPT_RESOLVE`, response size/time/redirect/page/depth limits. Numeric host tricks (`2130706433`, `0x7f000001`, `127.1`) fail closed.
* **Untrusted content.** Crawled text is data. It is plain-text-checked (no markup), length-limited, link-allowlisted (`#`, `/`, `https:`, `mailto:`, `tel:`),
  and escaped on output; JSON-LD is encoded so it cannot close its script tag. Tests assert structurally (DOM) that hostile strings stay inert.
* **Generated pages.** Static, no scripts except one data-only JSON-LD block. The in-app preview is a sandboxed iframe (`allow-same-origin` only
  so approved self-hosted fonts load — **no** `allow-scripts`).
* **Published sites** (`/sites/{slug}`): served with `Content-Security-Policy: default-src 'none'; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; font-src 'self' data:; form-action 'self' mailto:; base-uri 'none'; frame-ancestors 'self'`,
  `nosniff`, referrer and permissions policies. The analysis files (`redo/`, `design/`, `README.md`) are **only** in the customer's export ZIP, never on the public site.
* **Browser providers.** The local provider only opens `file://` artifacts REDO built. Only remote providers may be pointed at third-party URLs, and only after `SsrfGuard`.
  Tokens stay server-side.
* **Plans.** Free: preview only. Starter ($29) and Agency ($99): publish + HTML export. Export Pass: one-time HTML download, no publishing. Self-hosted edition: everything on.

## 6b. Reading a customer's site (bot challenges, JavaScript sites, the "before" screenshot)

The plain crawler cannot read sites that sit behind a bot-protection challenge (e.g. a proof-of-work page that answers HTTP 503 with a
page titled "POW") or that render with JavaScript. Previously it analysed the challenge page as if it were the website. Now:

1. **Content quality gate** (`ContentQualityAssessor`) runs before any model call. A challenge page, an HTTP error page or an almost empty
   JavaScript shell is *not content*.
2. If the gate fails and `REDO_SOURCE_CAPTURE` is on, **a real browser** (`scripts/visual-qa/capture-source.cjs`) clears the challenge,
   renders the site, reads up to 4 same-origin pages and takes a genuine desktop screenshot — the BEFORE image. Readable plain content is
   preferred over the browser copy; the browser is always used for the screenshot when enabled.
3. If the real content still cannot be read, the analysis **stops with a plain explanation** (`content_blocked` / `content_unreadable`)
   and no redesign is generated.

**Security.** The browser opens a URL chosen by a user, so *all* of its traffic is forced through `scripts/visual-qa/egress-proxy.cjs`, which
resolves each host once, requires every address to be public, and connects only to the address it validated (CGNAT, NAT64, 6to4, Teredo,
metadata, loopback, private and multicast ranges are refused; only ports 80/443/8080/8443). We tested the alternative — filtering
requests inside the browser — and it does **not** see redirect hops (an internal server was reached), which is why the proxy exists.
`node --test scripts/visual-qa/egress-proxy.test.cjs` proves, with a real browser, that an internal server is never contacted by
navigation, images, fetch, iframes or beacons. It still runs on *this* machine: keep `REDO_SOURCE_CAPTURE` off on shared hosting and
enable it only on an isolated worker (or use a remote browser provider).

**Limits.** Interactive CAPTCHAs / Turnstile that require a human cannot be cleared (the user is told, and no redesign is generated).
A capture takes roughly 20–70 s; the analysis job's time budget is 900 s. Screenshots are kept under `storage/app/public/site-captures`
(see retention).

**The hero image.** The redesign leads with the site's own lead photograph: the first large (≥1000px), landscape, genuinely photographic
image on its homepage. Flat decorative textures and square/portrait graphics are skipped; inventory role labels are not trusted.

## 7. The demo (repeatable from a clean project)

```bash
php artisan migrate:fresh --seed
php artisan directions:capture && php artisan blueprints:capture && php artisan fixtures:capture-originals
php artisan redo:demo brightleaf-dental          # or anchor-consulting
```

It prints the **Before & after** and **Interactive** URLs. To show paid delivery: register, subscribe to Starter (or insert a `subscriptions`
row), open the project's *Launch* page, then *Download HTML* or *Publish*. **For a real customer demo** use a site you have permission to
analyse and run the normal pipeline (needs `META_API_KEY`); the demo fixtures are fictional and their "before" is illustrative.

## 8. Cost limits

Model calls: one ranking call per recommendation, one spec + one evaluation call per generation (existing). v1.5 adds **no** model calls
(mapping, validation, QA and refinement are deterministic). Browser time is capped per project per day (§3). Screenshots/exports are time-limited (§3).

## 9. Known limitations

* **Browserless adapter is unverified.** Built on the documented `/function` endpoint and contract-tested with faked HTTP only. Plan, region, data terms and the exact response envelope need confirming with a real account.
* **The "before" screenshot needs a browser.** It is our own capture (§6b); where capture is off (production by default) the panel says a screenshot isn't available rather than showing a third-party placeholder. Demo fixtures use an illustrative original.
* **Placeholder imagery.** Sections with no approved image get brand-coloured generative art. Real photography depends on what the source site provides (or the existing stock/AI fallback tiers).
* **Thin sources produce short pages.** Optional sections without verified content are omitted. A model-authored, evidence-linked "process / pricing / FAQ" step would fill more, and is the main quality upgrade still available.
* **Contact forms use `mailto:`** and only exist when a contact email was found. A lead-inbox or webhook adapter is an open PRD decision.
* **Homepage only.** One page per site.
* **Direction screenshots are of fictional example brands** (labelled as examples). "Visually distinct" is enforced by a perceptual-distance threshold plus unique art style / font pairing / palette per direction — a guard, not a substitute for a designer's eye.
* **Direction switching in the preview** regenerates with the direction's legacy template, not a blueprint.
* **Shared hosting** (e.g. Opalstack) cannot run Chromium: use `REDO_BROWSER_PROVIDER=browserless` there, and run the capture commands on a dev/CI machine and commit the generated manifests/screenshots or run them on a worker.
* Fonts and screenshots live on local disk (`storage/app/public`); move to object storage before multi-server deployment.

## 10. Rollback

* Data: all v1.5 migrations are additive (new tables/columns, nullable). `design_spec_json['v15']` is additive; legacy rendering ignores it.
* Behaviour: `REDO_ACTIVATE_V15_DIRECTIONS=false` + reseed restores the original six directions. Blueprint-generated specs keep rendering regardless.
* Published sites are static files in `storage/app/private/sites/{slug}`; rollback to an earlier deployment is available from the Publish page.

## Deploying the layout preview checks (required, easy to forget)

A page layout (blueprint) only counts as **ready** — and so only produces an editable design — when its preview check files exist in
`storage/app/public/blueprint-previews/<blueprint>/<direction>/manifest.json`. Those files are generated on a development machine
(`php artisan blueprints:capture`) and are deliberately not in git or in the normal code upload (`storage/` is excluded).
**Upload them to every server whenever they change**, or no layout is "ready", every new design silently falls back to the older
generator, and the on-page editor cannot open it:

```sh
rsync -az -e "ssh -i <key>" storage/app/public/blueprint-previews/ <user>@<host>:<app>/storage/app/public/blueprint-previews/
```

Check on the server: `php artisan tinker --execute='echo count(app(App\Services\Recommendation\BlueprintRecommender::class)->eligible("trusted-expertise"));'` must be greater than 0.
