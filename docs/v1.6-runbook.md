# REDO v1.6 — Positioning Intelligence & Hero Engine: runbook

Backward compatible with v1.5: a project with no `design_spec_json['v16']` renders exactly as before (tested). Everything v1.6 adds is
new tables, a new optional `v16` block, and new services. Audit and gap matrix: `docs/v1.6-gap-analysis.md`.

## The flow

1. **Positioning profile** (`PositioningIntelligenceService`) — evidence-grounded claims about the business. A claim's status
   (`verified_source` / `user_confirmed` / `inferred` / `unknown` / `contradicted`) is **computed in code** by checking the
   claim's words and numbers against the cited source text; the model's own confidence is advisory only. Cross-page disagreements
   (e.g. two founding years) become `contradicted` and are kept out of copy until the owner resolves them.
2. **Diagnosis** (`HeroMessagingDiagnosisService`) — the 10 PRD checks, deterministic, each finding traceable and with a fix and a
   "belongs elsewhere" hint (product grades → product pages, years/branches → trust strip, history → About).
3. **Options** (`HeroCopyGenerationService`) — up to 3 options from distinct strategies (`config/hero_strategies.php`). The model writes
   and rates; **code** applies the hard factual gate, the editorial gate and the weighted score (25/20/15/15/10/10/5, thresholds 80/65).
   A failed hard gate is `rejected` whatever the model scored it. If nothing safe survives (or the model is down) a conservative
   option built only from verified facts is offered, never marked "recommended".
4. **Approve / edit / reject / restore** (`HeroCopyVersionService`, `SpecEditService`) — every change is a **new DesignSpec version**;
   history is never rewritten. `v16.hero_content` follows the PRD shape; legacy `hero` fields stay in sync.
5. **Measured fit** (`HeroLayoutValidationService` + `scripts/visual-qa/measure-hero.cjs`) — the production artifact is opened in
   Chromium at 1440 / 768 / 390, fonts and images awaited, and the hero's real line counts, overflow, clipping and CTA visibility are
   read from layout. Judged against per-variant preferred lines (`config/hero_layout.php`).
6. **Bounded refinement** (`HeroCopyRefinementService`) — if it does not fit: at most **2 copy rewrites** (each must pass both gates
   again), then at most **2 layout changes** (a roomier hero variant, only where the blueprint does not lock it). Type size is never
   changed (asserted, and recorded per attempt). If the bounds run out the owner decides: edit the wording or keep it as a recorded
   `layout_exception`.

## Honesty rules (do not weaken)

* A measurement that did not happen is never a pass: non-local browser providers → `unavailable`; fonts not ready → `exception`.
* A rewrite never reaches the page unless it passes the factual and editorial gates.
* A hand edit is trusted (the owner's own words) but gets inline warnings: unsupported numbers/claims are flagged "confirm", not blocked.
  Unsafe markup, unsafe links and destinations outside the page are always refused.
* Scores are an editorial estimate, not a measured conversion prediction, and are labelled so.

## Operations

* **Queue workers must be restarted after deploying** (`queue:work` keeps old code in memory; `queue:listen` reloads). A stale
  worker fails new job classes with "Call to undefined method".
* Hero measurement needs `REDO_BROWSER_PROVIDER=local` and Playwright + Chromium on the worker host. Elsewhere the fit check reports
  "can't measure here" and the editor says so.
* Model calls per full hero pass: 1 (profile) + 1 (options) + up to 2 (rewrites). Stages are logged in `model_call_logs`.
* Tunables: `config/hero_layout.php` (limits, weights, thresholds, `max_copy_refinements`, `max_layout_adjustments`, per-variant lines),
  `config/redo.php` → `capacity` (scan queue busy threshold / workers).
* MySQL enforces column widths that the sqlite test database does not: model-supplied strings are bounded before they are stored.

## Verified in a real browser / live model

* Measurement: a long headline wraps to 5+ lines on a phone, a short one fits, type size identical (`HeroFitBrowserTest`).
* Live loop on a fixture business: 9-line headline → rewrite → 4 lines → rewrite → 3 lines → pass, type size constant at 68px.
* In-place editor: inline text/CTA/picture editing, undo/redo, hero options, approve, fit check — driven with Playwright.

## Not built / known limits

* Fit measurement on Browserless (no DOM-measure support verified).
* AI rewrite suggestions for individual non-hero fields; moving sections up/down.
* Inline picture clicking is hero-only; other pictures are changed from the Page tab.

## Editor additions: automatic hero wording, text styling, links, layout, Save layout

- **First REDO applies the recommended hero wording.** After a first-round design is generated, `GenerateDesignSpecJob` calls `AutoHeroService`: positioning profile → options → the single option that is *recommended* and passed every hard factual gate is approved as the next spec version. No recommended option, a model outage or any error leaves the generated page untouched (options stay available in the editor's "Hero copy" tab). Refinements of an existing design skip it. Disable with `HERO_AUTO_APPLY=false` (the test suite does). The job timeout is now 420s — **restart queue workers after deploying.**
- **Presentation overrides** live beside each section's props as `overrides` (`fields[path] = {size, font, href}`, `layout = {width, split}`) and are applied by `SectionOverrides` to the rendered HTML. Sizes are 12–120 px (scaled down on narrow screens), fonts come only from `config/blueprint_fonts.php` (+ the two system stacks), links use the same safe-link rule as content (`https:`, `mailto:`, `tel:`, `#section`, `/path`; never `//host`), container widths are narrow/standard/wide/full, and the column split (30–70%) is offered for two-column sections. Sections without overrides render byte-for-byte as before.
- **Editor operations:** `set_style`, `set_link`, `set_layout` (plus `revert`, which also clears them). Links on buttons keep using `set_cta`.
- **Save layout:** edits autosave as a draft; `POST /analyses/{run}/edit/save` closes the draft as a saved layout (the next edit starts a new version, so the saved one stays restorable from History). The editor's Approve button saves first.
- Limits: text/picture styling is matched to the rendered element by its text (or alt text), as the click-to-edit bridge does — two identical strings in one section are styled in order.

## Journey, add-ons, billing (editor v2)

**Visitor journey:** homepage URL → (visitor) short sign-up (email + password, or Google; the URL is held in the session) → scan starts → on completion `analyses.express` picks the best-matching direction and its recommended layout and builds the REDO (first-round hero wording applied automatically) → Reveal → Edit → *Save layout* (free; shows a plan prompt on Free) / *Approve design* (needs a paid capability, otherwise → `analyses.upgrade`) → Stripe Checkout → back to Launch with the design approved → Publish or Download.

**Keys to add (see `.env.example`):** `STRIPE_KEY`, `STRIPE_SECRET`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_STARTER`, `STRIPE_PRICE_AGENCY`; `GOOGLE_CLIENT_ID/SECRET` (redirect `{APP_URL}/auth/google/callback`); `UNSPLASH_ACCESS_KEY`. Stripe webhook: `{APP_URL}/stripe/webhook` with events `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.payment_failed`. Run `php artisan migrate` (adds `users.google_id`, `users.stripe_customer_id`, subscription Stripe columns). Without Stripe keys, paid plans can only be switched in local/testing; in production nothing paid is handed out.

**Add-on widgets** live in `v15.pages[0].widgets` (see `WidgetCatalog`). Published pages are strict-CSP static HTML; a page only gets `script-src` / `frame-src` when it ships the widgets script or an iframe. Embed code is written to `embeds/{id}.html` and served with `Content-Security-Policy: sandbox …` (opaque origin) — it can never touch the site's own origin. Google Analytics only loads on the published page.

**Images:** uploads keep PNG/WebP transparency and format (JPEG stays JPEG). Unsplash photos are fetched server-side from `images.unsplash.com` only, re-encoded like uploads, credited to the photographer, and reported to Unsplash's download endpoint.
